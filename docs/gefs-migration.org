#+TITLE: Root on gefs+: the migration (started 2026-10-17)

gefs+ = lambda-symbolics/gefs-netbsd (9front gefs as a NetBSD kernel file
system, plus group commit, commit policy, the 2026-10-14 review fixes,
batched deadlist merges, workers parked on suspend).  Still readable by
9front gefs.  Value here: snapshots and boot environments; power-wise it
is a wash with APST on (measured 2026-09-28, docs/power-levers.org).

* The procedure (agreed 2026-10-14)
1. Back up the root to the 512 GB USB-C SSD as FFS and boot from it: proves
   the copy is complete and that this firmware boots from USB.  Kept
   afterwards as the rollback image.
2. gefs+ trial on the same SSD: a second partition, gefs+, the system
   copied in, the gefs-aware loader on the SSD's ESP.  Boot it and live on
   it for a day: Mahogany, Wi-Fi, lid suspend/resume, a crash dump, a few
   snapshots, a =boot @label/netbsd= rollback.  Internal disk untouched.
3. Only then the internal root wedge (dk1 only) becomes gefs+: copy back,
   loader on the internal ESP, boot entries switched.  Swap/dump (dk2)
   untouched; the old FFS loader stays on the ESP under another name.

* Booting from the USB-C SSD (phases 1 and 2)
- The firmware loads the loader and kernel through its own USB stack, and the
  kernel attaches xhci0 and the SSD during autoconfiguration, before root is
  mounted: booting needs nothing special.
- But =/etc/rc.local= runs =usb off= (all controllers), which would power the
  USB-C controller off under the mounted root.  On every copy that boots from
  the SSD, rc.local must say =usb off pch= (internal Bluetooth, camera and
  fingerprint reader still powered down; USB-C stays on).  The kernel's
  populated-controller guard (lispbsd-usb-populated) would refuse the power
  cut anyway; do not rely on it.  Back to =usb off= on the internal gefs root
  in phase 3.
- Lid suspend with a USB root is harder than the final setup: s2idle suspends
  and resumes xhci0 under the root disk.  Test it in phase 2, but a failure
  there is about USB, not gefs; skip it on the SSD rather than block phase 3.

* Laptop tree layout

=/usr/src/sys/lib/libsa/gefs.[ch]= are symlinks into

commit).  The NetBSD-side hooks are in nanobsd kernel/ (8bffbed): conf/files,
fs/Makefile, modules/Makefile, lib/libsa/Makefile, efiboot conf.c and
Makefile.efiboot, GENERIC.  Previous versions on the laptop: =*.180=.
