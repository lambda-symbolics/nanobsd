#+TITLE: lpsched — a laptop power governor for NetBSD (LISPBSD)
#+DATE: 2026-09-19

* Why

The awake-idle wakeup investigation (2026-09-19) showed the kernel's tickless
idle path (cidle) works, but never gets a quiet window: userland keeps waking
cores, and the stock scheduler makes it worse by *spreading* work for
throughput.  NetBSD's two schedulers (4BSD, M2) share one CPU picker in
=kern/kern_runq.c= that knows the SMT/core/package topology but has zero
idle-depth or power awareness, no wakeup coalescing, and no coupling to the
HWP frequency governor.  Linux fills these gaps with idle-state-aware placement,
timer slack and schedutil; NetBSD has none of them.

lpsched adds the three missing laptop pieces without rewriting a scheduler.
Expected: tenths of a watt from packing/coalescing, ~1 W-class from the EPP
coupling (measured EPP 128->255 = ~1 W on this box), and zero interactive
regression.  The main value is that these are genuinely missing NetBSD laptop
capabilities.

* Design (approved 2026-09-19)

Three policy-free in-kernel *mechanisms* under =machdep.lpsched.*=, one
userland *policy daemon*, one *stumpwm hook*.  Master switch
=machdep.lpsched.enabled=0= gives exact stock behaviour.

** Mechanism A — idle-aware packing (=kern/kern_runq.c=)
- cidle exports a per-CPU idle depth (=lpsched_idle_depth[]=: active /
  shallow MWAIT / tickless-deep MWAIT).
- =sched_takecpu()=: when =pack>0= and the LWP is *not exempt*,
  =lpsched_pack_pick()= chooses the cheapest CPU to wake: an idle SMT sibling
  of a busy core (core already awake, cost 0) > shallow-idle > deep-idle.
  =pack=2= will rather queue behind a running LWP on an awake CPU with an
  empty run queue than wake a sleeping core.  NULL -> stock placement.
- Exempt (always stock, latency-first): non-SCHED_OTHER classes, the focused
  process (=fgpid=), interactive LWPs (=l_estcpu >> 11 < estcpu_thresh=,
  default 2 — new threads inherit the parent's estcpu, so children of
  CPU-bound parents are packed, children of interactive ones are not).
- =sched_idle()= / =sched_catchlwp()=: =lpsched_min_catch()= raises the steal
  threshold by =pack= for a CPU whose whole physical core is asleep, so a
  gated core is not woken to steal one stray LWP.
- Never oversubscribes: only returns idle CPUs (or, pack=2, an empty-queue
  running CPU); with nothing idle it falls through to stock.

** Mechanism B — callout coalescing (=kern/kern_timeout.c=)
- =lpsched_coalesce()= in =callout_schedule_locked()= rounds a non-precise
  callout's absolute expiry *up* to the =coalesce_ms= grid (hz=100, so 50 ms
  = 5 ticks).  Timers fire in clusters; idle gaps lengthen; cidle's
  =callout_next_ticks()= sees the rounded time and skips further.
- Only delays, never fires early; unsigned modulus so a wrapped tick counter
  still rounds upward; =to_ticks==0= (immediate) untouched.
- New =CALLOUT_PRECISE= (0x0200, =sys/callout.h=) exempts time-critical
  callouts.  Nothing is marked yet; mark on evidence.

** Mechanism C — signals
- =lpsched_last_input= set from =wskbd_input()= / =wsmouse_input()=; exported
  as =machdep.lpsched.idle_ms= (RO).
- =machdep.lpsched.fgpid= (RW): focused PID from the WM.

** Governor daemon — =lpschedd(8)= (=userland/lpschedd.c=, /usr/local/sbin)
- Policy lives in userland: trivial to retune without a reboot, easy to read
  battery/AC, and it matches the existing mechanism-in-kernel/policy-outside
  split (hwp/cidle).  An in-kernel kthread governor was rejected.
- Inputs: AC from =/var/run/lpsched.ac= (written by powerd's =acadapter=
  hook, seeded from =envstat -d acpiacad0= at start), 1-min load,
  =idle_ms=, and =fgpid <pid>= datagrams on =/var/run/lpsched.sock=.
- Outputs: =machdep.hwp.epp=, =machdep.lpsched.{enabled,pack,coalesce_ms,fgpid}=.
- Profiles:
  | profile   | EPP | pack | coalesce | when                                  |
  |-----------+-----+------+----------+---------------------------------------|
  | perf      |  32 |    0 |     0 ms | AC present (always); battery+load>1.5 |
  | balanced  | 128 |    1 |    20 ms | battery + input within 10 s           |
  | powersave | 240 |    2 |    50 ms | battery + idle                        |
- Upshifts immediate; downshifts need 3 consecutive polls; load latch
  releases below 1.0.  Poll 250 ms active / 500 ms in powersave via
  =poll()= on the socket (the daemon's own timer is itself coalesced).
- On exit: enabled=0, pack=0, coalesce=0, fgpid=0, EPP restored.
- =rc.d/lpschedd= (=lpschedd=YES=), REQUIRE powerd.  The =acadapter= powerd
  script no longer sets EPP (it would fight the daemon); it records AC state.

** stumpwm hook — =dotfiles/.stumpwm.d/lpsched.lisp=
=*focus-window-hook*= sends =fgpid <_NET_WM_PID>= (0 on no focus) as one
datagram to the daemon socket.  Non-blocking, every error swallowed, keeps
stumpwm unprivileged (socket is 0666).  Loaded from =.stumpwmrc=.

* Measurement / success criteria
Same rig as the S0ix work: =envstat -d acpibat0= discharge (55 s settle) on
battery at screen-off and screen-on-idle; =machdep.cidle.tlstats= deep-skip
rate; =vmstat -i= deltas; interactivity by feel.  Each mechanism is A/B'd in
isolation via its own sysctl with the daemon stopped, then the daemon on.
Win = higher deep-skip rate + EPP watt saving on battery-idle, no perceptible
input lag, no audio glitches.

** Verdict
- Neither packing nor coalescing changes idle battery draw measurably: every
  config sits within the ~±0.05 W noise of the EC discharge average.  The
  run-1 "pack saves ~0.15 W" is not supported by run 2 and is withdrawn.
- Coalescing raises cidle deep skips a little (7-9 -> 9-10 /s) with no power
  effect.  The ~300/s early-wake floor is unchanged by both: with only ~55
  device interrupts/s, those wakes are cross-CPU IPIs/reschedules from
  X/stumpwm/statusbard — software, not callouts — which neither lever touches.
- The mechanisms are correct and safe (no regression, no interactive lag
  noticed, WM hook and stale-PID handling verified), but on this box the only
  watt-class lever is EPP (128->255 = ~1.1 W measured earlier), which
  =lpschedd= now drives automatically from AC/battery, load and input idle.
- Untested, and the fair test for packing: a light *background* load (idle
  is the worst case — there is nothing to pack).  Also unmeasured: the
  latency cost of pack=2 under load.
- Operational: never touch the daemon or open windows while =lpsched-ab= runs;
  the EC discharge figure needs >=50 s settle; the panel blanks after 5 min
  idle (=xset dpms 300=) and shifts the baseline by ~1.4 W.

Four =poller(1)= background tasks (~5% duty each), on AC so watts are not

- STILL MISSING: watts.  This run was on AC.  The same comparison on battery
  is required before claiming any power result, and the pack=2 latency cost
  under load is still unmeasured.

|--------------+------+--------+--------+----------+--------|
| stock        | 2.91 |    3.1 |  150.9 |      0.0 |    0.0 |

That looks like 0.23 W (~8%), but the values fall monotonically in run order,

- The pre-run idle baseline was 2.811 W before one run and 2.494 W before the

  larger than the claimed effect.
- Interleaved A/B/A/B under the same load:

| config    |    W | deep/s | ints/s | packed/s |
|-----------+------+--------+--------+----------|
| stock     | 2.67 |    1.6 |  122.7 |      0.0 |
| pack=2    | 2.70 |    5.1 |  121.2 |    232.5 |
| stock(2)  | 3.18 |    6.3 |  141.0 |      0.0 |
| pack=2(2) | 2.75 |    6.8 |  120.8 |    251.1 |

  The two *stock* samples differ by 0.51 W from each other -- more than any
  effect under test.  The single-pass 0.23 W is withdrawn.

*Conclusion.*  What is established: the mechanism executes (packed/s 0 ->
230-250, exactly what the pre-repair kernel could not do) and the
=sched_preempted= repair fires 20-40 times/s.  What is NOT established: any
power benefit, and also not the earlier "deep/s 0.6 -> 7.6, ~12x" reading --
stock's own deep/s ranged 1.6 to 6.3 across samples here, straddling the
packed numbers.  Both were single-sample artifacts.

*The rig, not the mechanism, is now the limit.*  A 20 s sample of an EC
discharge average that itself needs ~55 s to settle cannot resolve 0.2 W.
Next measurement should use *RAPL package energy* (MSR_PKG_ENERGY_STATUS
0x611, units in 0x606 -- already used for the S0ix work): it integrates
exactly, has no averaging lag, and isolates the package from panel/board
noise.  Then >=3 interleaved repetitions per config with multi-minute
samples, and a workload with deterministic phase (the pollers free-run, which
likely drives the deep/s variance).

* Review and repairs (2026-09-20, external review of 8a7cf67)

An external review found seven defects; all seven were verified against the
source before any change.  The important consequence is that the earlier
"no measurable idle-power improvement" result **does not establish that the
mechanisms are useless** -- the classifier exempted the workload they target,
the "stock" baseline was not clean, and there were no counters to show
whether packing ever executed.  Treat the first round as "untested".

1. *Stock migration undid packing.*  =sched_preempted()= exists to move a
   thread off a secondary SMT CPU onto an idle first-class CPU -- exactly
   where packing had just placed it, waking the core packing avoided.  It had
   no lpsched check.  Fixed: packed, non-exempt LWPs are left in place
   (vfork LP_TELEPORT still scatters, that is correctness not preference).
   Counter: =pack_held=.
2. *=pack=2= could strand work.*  It queued behind any running thread with an
   empty queue, with no priority check, while =lpsched_min_catch()= raised the
   steal threshold to 3 -- so a background LWP could sit behind realtime work
   that it cannot preempt on a CPU an idle core declines to rescue.  Fixed:
   only queue behind timeshare work (=spc_curpriority <= MAXPRI_USER=), and
   never raise the steal threshold when the remote queue holds anything above
   timeshare.  The threshold is applied before the candidate LWP is examined,
   so that guard is the only place realtime work can be protected there.
3. *The coalescing grid was per-CPU.*  It rounded on =cc_ticks=, which each
   callout_cpu advances itself, so "multiples of 5" on different CPUs are
   different instants and wakeups never clustered across the package -- the
   entire point.  Fixed: align on =getticks()=, which is advanced only under
   =CPU_IS_PRIMARY= and is therefore shared, then apply the resulting delay in
   the local domain.  Residual per-CPU tick *phase* is still uncorrected, as
   are the pre-existing =lapic_oneshot_done()= rounding issues.
4. *The classifier exempted the target workload.*  =estcpu>>11 < 2= exempts
   every LWP under 4096 estcpu, i.e. precisely the low-duty-cycle background
   pollers packing exists to gather; and =l_estcpu= is SCHED_4BSD-only, so
   under SCHED_M2 it reads 0 and exempts everything.  Fixed: threshold
   defaults to 0 (test disabled); latency protection now rests on scheduling
   class and =fgpid=.  Counters split exemptions by reason.
5. *Coalescing applied to every unmarked callout.*  =CALLOUT_PRECISE= is
   opt-out and nothing marks it, so a one-tick timeout could become five.
   Fixed: bounded slack -- only timers already longer than the grid are
   relaxed (=to_ticks >= 2 * grid=), keeping added delay under half the
   request.  Counters: =coal_applied=, =coal_short=, =coal_precise=.
6. *The idle-depth array was measurement-induced contention.*  A bare
   =uint8_t[MAXCPUS]= put all 8 CPUs' bytes in one 64-byte line and was
   written on every idle entry and exit even with lpsched disabled, so
   "disabled" was not a stock baseline.  Fixed: =struct lpsched_cpu= is
   =__aligned(COHERENCY_UNIT)=, one line per CPU, and writes are gated on
   =lpsched_enabled=.
7. *Rates divided by requested sleep.*  =lpsched-ab= now divides by measured
   elapsed time and prints the counters, so a mechanism that never ran is
   distinguishable from one that ran and did nothing.  It also tolerates AC
   (printing =--= for watts) and gained a =load= mode driving =poller(1)=
   low-duty-cycle background tasks, because static idle has nothing to pack.

Not addressed (pre-existing, outside lpsched): =lapic_oneshot_done()= floors
elapsed time to whole ticks and restarts a fresh interval after an early
wake, and =woke_early= does not identify what woke the CPU -- so the earlier
"~300/s early wakes are X/StumpWM IPIs" claim was inference, not attribution.

* Second review and repairs (2026-09-20, review of 51ab864)

A second external review found the instrumentation itself misleading.  All
four findings verified in source before changing anything.

1. *=pack_held= counted non-events.*  The suppression sat BEFORE the stock
   early return, so it fired for threads already on a first-class CPU that
   stock would have left alone anyway, and it also suppressed the *same-core*
   sibling move, which shares the core and wakes nothing.  Fixed: the check
   now sits at the one place a migration certainly would have happened -- the
   =sched_bestcpu()= cross-core move -- and only when =lpsched_same_core()= is
   false.  =lpsched_is_packed()= additionally releases a thread once its core
   has emptied, so suppression ends when the load it was protecting does.
2. *Placement counters were summed.*  =pack_sibling + shallow + deep + busy=
   hides that a "packed" decision may have WOKEN a deep-idle core.  They are
   now reported separately, and the first run showed exactly why: 131
   =pack_deep= events were previously being counted as consolidation.
3. *The counters were global atomics.*  Every event was an atomic increment on
   a line shared by all CPUs -- the same cross-CPU traffic this code exists to
   avoid, added only in the power-saving configuration, i.e. taxing the arm
   under test.  Now per-CPU inside the cache-line-aligned =struct lpsched_cpu=,
   summed on read, with =machdep.lpsched.stats_enabled= to measure their cost.
   =catch_held= also fired while scanning CPUs with EMPTY queues; it now only
   counts when the raised threshold actually rejects work that was there.
4. *The coalescing benchmark could not exercise coalescing.*  The pollers slept
   20 ms = 2 ticks, below the 10-tick cutoff, so the =coal/s= reported came
   from unrelated callouts.  =poller(1)= now takes a period, and uses ABSOLUTE
   deadlines: the old fixed-work-then-relative-sleep loop let the period
   stretch with scheduling, so neither phase nor duty cycle was constant
   across the configurations being compared.  It reports batches completed and
   deadlines missed so a run that quietly did less work cannot read as a win.

** Coalescing is now opt-in, and therefore inert
=CALLOUT_SLACK= (0x0400) must be set by the callout's owner.  A duration
threshold bounds how far a timeout is stretched but says nothing about whether
its caller tolerates the delay, and callout(9) documents the requested time as
the time requested.  Nothing in the tree sets the flag, so =coal_applied= is 0
and =coal_noslack= counts thousands of declined callouts -- inert by design
until specific housekeeping timers are audited and marked.

** Tickless accounting: measured and repaired (third review)

A third review showed the carry alone could not be right, with a
counterexample: =lapic_oneshot()= overwrites the timer without accounting for
how far the CURRENT periodic interval has already progressed, so that time
never enters =lapic_oneshot_done()='s measurement and no amount of carrying
the remainder recovers it.  Modelled first, per the reviewer's advice, in
=tests/tickless-model.py=: the constructed case (0.3 tick awake, 0.7 tick
asleep, x100) loses 30%; a mixed workload loses 2.8%; adding entry capture
takes both to exactly 0.  =lapic_oneshot()= now banks =lapic_tval - CCR= into
the carry before reprogramming.

Measured with the corrected probe, pinned to CPU 0 (=schedctl -A 0=):

| kernel                        | tickless ON | tickless OFF |
|-------------------------------+-------------+--------------|
| #94 before any repair         |     -4.412% |      -0.003% |
| #97 carry of remainder only   |     -0.816% |      +0.003% |
| #98 carry + entry capture     |     -0.041% |      -0.001% |

Confirmed by three independent pinned runs on #98: -0.041%, -0.051%, -0.038%
(mean -0.043%, spread 0.013%), so hardclock went from 4.4% slow under tickless
idle to within 0.05% of the periodic control -- about a hundredfold
improvement on where this started.  "Rate-exact by construction" in the previous section was
WRONG: carrying the remainder is only half the accounting.

The probe was also defective and was fixed first: =clock_nanosleep(2)= returns
the error number directly, so testing for -1 never retried an interrupted
sleep.  It must be run pinned, because only the primary CPU advances
=hardclock_ticks= and sampling elsewhere can read outstanding-but-uncredited
time as lost.  Pinning did not shrink the #97 residual, confirming that part
was genuinely lost time.

*Known and unfixed:* =lapic_oneshot_done()= still treats a pending timer
vector as completion of the interval it programmed, without checking whether
that vector was already pending from the previous periodic timer.  A unified
accounting path (=ticks_due = floor(elapsed_from_epoch x hz)= over a
free-running source, shared by periodic entry, one-shot entry and one-shot
exit) would remove the ambiguity.  With the measured error now at 0.04% that
rewrite is not justified by evidence yet; revisit if a case appears.

** Superseded: earlier partial repair
=lapic_oneshot_done()= floored =counted / lapic_tval= and discarded the
sub-tick remainder on every wake.  Measured with =tickrate(1)= (nanosecond
monotonic clock against =kern.hardclock_ticks=; shell sampling quantises to
whole seconds, far coarser than the error):

| kernel                  | tickless ON | tickless OFF |
|-------------------------+-------------+--------------|
| #94 before the repair   |     -4.412% |      -0.003% |
| #97 carry of remainder  |     -1.036% |      -0.003% |

So hardclock really was running 4.4% slow whenever tickless idle was enabled --
a 60 s sleep took 62.7 s -- and carrying the remainder cuts that four-fold.
~1% remains, most likely the =pending= path crediting exactly =nticks= and
ignoring time spent asleep past expiry.

*Phase alignment was attempted and reverted, with evidence.*  Restarting as a
short one-shot to land on the original tick boundary is correct only if that
one-shot survives to fire; =lapic_oneshot()= reprograms the timer on every
re-entry to tickless idle (tens of thousands per minute here), so it was
usually cancelled and the tick it owed was lost.  Measured -3.3%.  Carry-only
is rate-exact by construction and was kept.  Cross-CPU tick PHASE therefore
remains unaligned, so the coalescing grid still cannot guarantee synchronized
physical wake times -- a correct scheme must return the unelapsed part of a
cancelled interval to the carry.

* Fourth review: benchmark repairs and the energy harness (2026-09-20)

** Two interrupt-ordering bugs remain, carried as failing regression tests
The reviewer supplied a register-level reproducer, kept verbatim at
=tests/timer-reproducer.c=.  Built and run against the committed arithmetic it
confirms two cases the entry-capture fix does NOT address:

| case                                             | due | credited |
|--------------------------------------------------+-----+----------|
| entry capture + early wake (fixed in #98)        |   1 |  1 PASS  |
| old periodic IRQ pending before arming a one-shot|   1 |  4 BUG   |
| expiry racing the IRR/CCR reads at exit          |   4 |  5 BUG   |

Both OVER-credit, which is exactly why the good average-rate result (-0.041%)
does not prove interrupt accounting: rare over-credits offset residual
under-credit in the mean.  =lapic_oneshot_done()= reads IRR before CCR and
treats a pending vector as completion of the interval it programmed, without
checking whether that vector was already pending from the previous periodic
timer.  The repair must account for an old pending event, and for an expiry
racing the exit snapshot, exactly once.  =tests/tickless-model.py= cannot
exercise either case -- it supplies elapsed time directly and never models the
counter/pending inference -- so it stays as a fractional-accounting test only.
Deferred deliberately: the reviewer's direction is to get an energy result
first, and the clock path has already been destabilised twice today.

** Benchmark defects fixed
- =lpsched-ab= overwrote its configuration label: =set -- $(work_snapshot)=
  replaces the positional parameters, so =$1= became a batch count and every
  row was labelled with a number.  The label is now saved first.
- Work counts and elapsed time covered different intervals.  The snapshots
  bracket the timed window, so dividing work by the sample elapsed divided
  ~21 s of work by 20 s, a ~5% rate error.  =poller(1)= now reports a sequence
  number and a monotonic timestamp on SIGUSR1; the harness proves freshness by
  sequence, divides work by the WORKERS' own interval, and prints snapshot
  freshness and skew instead of assuming them.

** Energy harness
=machdep.cidle.rapl= exposes the RAPL package energy counter (MSR 0x611) and
unit exponent (MSR 0x606), added to the cidle module so it needs only a module
reload, no kernel rebuild.  The harness reports package watts and joules per
completed batch alongside the battery figure.  Package energy integrates
exactly and has no averaging lag, unlike the EC discharge average whose drift
(0.3 W between identical idle samples) exceeded the effects under test.
