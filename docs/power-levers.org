#+TITLE: Power levers left after the Wayland switch
#+DATE: 2026-09-27

What was still worth doing once the Mahogany session, RC6 re-arm, the
on-demand bar and the futex SBCL were in (see =mahogany.org=).  Measured on
battery, kernel 129, idle, screen blanked, before any change below.

* Where the power went

| what                              | measured                                   |
|-----------------------------------+--------------------------------------------|
| package (RAPL)                    | 1.40-1.46 W                                |
| cores                             | C7 99 %                                    |
| package states                    | PC3 about 50 %, PC10 about 44 %            |
| same state on 9/26, no Firefox    | 0.84 W                                     |
| wake events                       | about 100/s                                |
| Firefox (all processes)           | about 46 wakeups/s, one tab about 14/s     |
| TLB shootdown IPIs                | 28-55/s                                    |
| iwx interrupts (beacons)          | about 10.5/s, each with a bounce copy      |
| ntpd                              | 1.5 wakeups/s                              |
| hdaudio                           | 1-2.5 interrupts/s (jack sense polling)    |
| Mahogany, cclsh, waytemp          | about 0                                    |

Cores sleep deeply but the package keeps waking: every wake event ends the
package idle period, and with ~100/s the PCU often picks PC3 over PC10.

Census method: =vmstat -e= and =vmstat -i= deltas, per-process =nvcsw+nivcsw=
(=ps -o= needs one =-o= per keyword on NetBSD), =machdep.cidle.rapl= and
=machdep.cidle.residency=, with every exec kept outside the sampling window
(the probe's own execs showed up as TLB shootdowns and vmcmd events).

* The levers

1. *Mahogany on the GPU.*  =startmh= forced the pixman renderer because the
   render engines were wedged; that stopped being true with the ELSP fix of
   9/16.  A headless Mahogany with =WLR_RENDERER=gles2= comes up on "Mesa
   Intel(R) Xe Graphics (TGL GT2)".  Clients still fell back to llvmpipe:
   Mesa 21.3.9 binds =zwp_linux_dmabuf_v1= at version 3 only, so it cannot use
   dmabuf feedback to find the GPU and needs a =wl_drm= global, which heart
   never created.  Fix: =wlr_drm_create()= in =heart/src/server.c=.  llvmpipe
   splits each frame across one thread per CPU, so today every keystroke in
   alacritty wakes every core; Firefox renders with software WebRender.
2. *Firefox at idle.*  The difference from the 9/26 measurement (0.6 W of
   package) is probably Firefox: its wakeups, and its unmaps turning into
   TLB shootdowns across CPUs.
3. *Lid suspend.*  =/etc/lid-nosuspend= (temporary, for the Firefox build)
   makes lid close only blank the panel: about 2.95 W instead of 2.02 W in
   s2idle.
4. *iwx beacon filtering.*  =if_iwx.c= never enables it: =sc_bf.bf_enabled=
   is only ever cleared, so every beacon interrupts the host and
   =iwx_update_beacon_abort= is a no-op.  Linux and FreeBSD enable it on
   association.
5. *TLB IPIs to idle CPUs.*  =x86_tlb.c= targets =pm_cpus=, which still
   contains CPUs that went idle with the process's pmap loaded lazily; such a
   CPU only leaves the set in =pmap_tlb_intr=, after the IPI woke it.  Linux
   skips lazy CPUs and lets them flush when they switch back.
6. *Framebuffer compression.*  =enable_fbc= sanitizes to 0 because
   =HAS_FBC= is cleared when =mm.stolen= is uninitialized, and NetBSD fills
   =intel_graphics_stolen_res= only through =agp_i810=, which never attaches
   on Tiger Lake.  The GPU's own config space has it (BDSM 0xC0 =
   0x9c800001, GGC 0x50 = 0x2c1: 64 MB).  The 5.6 FBC code also insists on a
   CPU fence; Linux later made fences optional on gen9+.  PSR is impossible on
   this panel, so this is the last display-side lever.
7. *Small ones.*  i915 is a debug build that checks for unclaimed MMIO around
   every register access (=mmio_debug=-1=); ntpd wakes 1.5/s; hdafg polls the
   jacks.  Codec power-down is left alone (buzz risk).

Not worth more time: PSR (panel DPCD 0), scheduler packing and timer
coalescing (measured null, =lpsched-design.org=), SLP_S0 (firmware wall,
=rpm-s0ix-findings.org=), NVMe APST and ASPM L1.2 (already on), hardware video
decode (no Gen12 VA-API driver in pkgsrc).

* Results (2026-09-27, kernel 130)

** 1. Mahogany on the GPU: done
heart creates =wl_drm= (lambda-symbolics/mahogany 5eb005a), and =startmh=
defaults to =WLR_RENDERER=gles2= and retries with pixman if the compositor
dies within 15 s of starting.

An apparent Firefox crash at exit under the GLES2 compositor turned out to be
the test harness.  Firefox rewrites its argv (the parent shows only
=firefox URL=), so the harness's =pgrep -f "profile ..."= matched nothing,
Firefox was never told to quit, and it was still running when the harness
killed the compositor.  A GTK client that loses its display aborts; Firefox
turns that into SIGSEGV after =WaylandMessage::Write() failed : Broken pipe=.
Killing the compositor under Firefox reproduces it with pixman too, while
SIGTERM to the Firefox PID exits cleanly with its Wayland proxy on (4 of 4).
So Firefox keeps its proxy; a brief =MOZ_DISABLE_WAYLAND_PROXY=1= in =startmh=
was reverted.
Package power (RAPL), panel at brightness 15:

| workload                       | pixman                 | GLES2                |
|--------------------------------+------------------------+----------------------|
| idle, panel on                 | 2.77 W                 | 2.55 W               |
| alacritty, ~100 lines/s        | 4.78 W, alacritty 215% | 2.37 W, alacritty 10% |
| Firefox, CSS animation         | 12.19 W                | 4.75 W, Firefox 30%  |

The scanout buffer is now Y-tiled with render compression (=PLANE_CTL= A
=0x8400b000=), which the display reads compressed.

The benchmark profile has no frame-rate cap, so Firefox ran at 60 fps for
those numbers.  The live profile's =user.js= capped it at 30 since 9/19 (to
halve i915 repaint interrupts under X); the cap is gone, so animated pages
run at the display's rate and keep the panel at 60 Hz, where a steady 30 fps
could let =refresh.lisp= drop it to 30 Hz.

** 2. Firefox at idle: the guess was wrong
With Firefox killed the package stayed at 2.0 W with the same ~50 % PC3.
Firefox was most of the wakeups but not the cost; see 8.

** 3. Lid suspend: back on, with Wi-Fi kept up
=/etc/lid-nosuspend= is gone (a copy sits in =/var/tmp=), so closing the
lid runs =s0ix suspend= again.  The freeze had only ever been tested under X;
under Mahogany a timed freeze (=hw.acpi.sleep.freeze_timeout=) with the panel
lit came back with the same compositor process, the pipe scanning out, and a
new GPU-rendered terminal window.  =wsdisplay_handlex()= has nothing to hand
off without an X-style VT process, so the freeze starts straight away.
=hw.acpi.sleep.freeze_keep_net=1= (kernel 130, now in sysctl.conf) leaves
iwx running through the freeze: resume needs no rescan, and see 9.

** 4. iwx beacon filtering: done
=hw.iwx.beacon_filter= (kernel 130) sends the firmware's beacon filter
command at association and when set at runtime (no reassociation).  iwx
interrupts went from 16.3/s to 1.1/s with the link up.  Beacon abort in power
save now works too, since it depended on the filter being on.

** 5. TLB IPIs to lazy CPUs: done
=machdep.tlb_lazyskip= (kernel 130): the initiator CASes a lazy target from
=TLBSTATE_LAZY= to the new =TLBSTATE_FLUSH= instead of interrupting it;
=pmap_reactivate= claims its state with a CAS and flushes if it was marked;
switching to another pmap reloads =%cr3= anyway (no PCID without SVS).
Packets that free page-table pages or touch kernel VAs still go to every
target, as in Linux.  =userland/tlbtest.c= remaps a page between two memfd
pages (or revokes it) while the reader's CPU idles lazily, and checks what
the reader sees: 700 000 checks, 0 stale, with 1.75 million lazy CPUs skipped
in 4 s; the same with a spin that guarantees the reader's CPU is idle.  A
30-minute soak (189 runs, about 26 million checks) found 0 stale reads.
Idle with nothing running (panel blanked, on AC), interleaved off/on/off/on:
shootdown rounds 2.0/s -> 1.6/s with about 6 lazy CPUs skipped per second,
package 0.23 -> 0.19 W, which is inside the noise.  The saving scales with
multithreaded programs: with Firefox open before the reboot, shootdowns ran at
28-55 rounds a second.

** 6. Framebuffer compression: not done, superseded
The GPU session scans out a render-compressed surface, and FBC and render
compression exclude each other, so FBC would only help the pixman fallback.
For the record, NetBSD never registers stolen memory on Gen11+:
=intel_gtt_get()= fills =intel_graphics_stolen_res= only via =agp_i810=,
which does not attach on Tiger Lake, so =HAS_FBC= is cleared at init.

** 7. Small ones: done
=hw.drm2.i915_modparams.mmio_debug=0= in sysctl.conf.  ntpd is off; the
dhcpcd exit hook runs ntpdate when a lease is bound and root's crontab runs it
hourly.  hdafg rewrites the pin controls only when jack presence changes, and
every 10 s as before otherwise, instead of every second.

** 8. The sticky PC3 state (new)
After the reboot into kernel 130 the blanked, idle package sits at 94-96 %
PC10 and 0.19-0.23 W, with =hw.acpi.sleep.idle_d3= off or on alike (it only
changes Thunderbolt DMA 1, the other driverless IPs already report D3).  The
boot before had been at ~50 % PC3 and 1.4-2.0 W for hours, and killing Firefox
did not change it: some event puts the platform into PC3 until the next
reboot, like the repeat-cycle regression in =rpm-s0ix-findings.org= (U42).
Or the power source does: the PC3 boot ran on battery, and the charger was
connected at the kernel 130 boot, so the two measurements differ in that too.
=/var/tmp/pclog.sh= samples residency every 5 minutes with the lid, USB,
panel and process state to catch the trigger.

** 9. SLP_S0 is reachable (new)
Every timed freeze with Wi-Fi kept up reached S0ix, which no earlier
experiment had (=rpm-s0ix-findings.org= concluded it was firmware-walled):

| 120 s hold, Wi-Fi up          | PC10 | SLP_S0 residency | package |
|-------------------------------+------+------------------+---------|
| beacon filter on, idle_d3 on  | 96 % | 110 s            | 0.19 W  |
| beacon filter off, idle_d3 on | 96 % | 109 s            | 0.22 W  |
| beacon filter on, idle_d3 off | 97 % | 112 s            | 0.17 W  |

(LPIT counter at 8197 Hz, from the kernel's =s2idle: slp_s0 delta= line.)
The earlier attempts either suspended iwx for the hold, or ran while the
package was in the PC3 state of 8.  Leaving the CNVi to its firmware power
save appears to be what the PMC wanted.

*Caveat:* the charger was connected for the whole kernel 130 session (AC
from 13:35), both for 8 and for these holds.  The whole-machine power in
S0ix and whether the battery case behaves the same still need a run on
battery: close the lid unplugged for a few minutes and look for =slp_s0
delta= in =/var/log/messages=, and the discharge rate before and after.
