#+title: Selective-s2idle filesystem barrier

* Contract

=acpi_enter_freeze()= requests userspace suspension, then verifies that every
other non-system LWP has reached =LSSUSPENDED= or exited. In-flight syscalls
or newly created LWPs cause an =EBUSY= abort and thaw, before storage suspend.
It then calls =vfs_suspend_all()=. The helper takes a
nonblocking iterator pass over the live mount list.  The base VFS iterator
extension in =kernel/kern/vfs_mount_s2idle.patch= reports mounts that its
try-busy operation skipped; any such skip aborts the session rather than
silently producing a partial barrier.  Each admitted mount receives an
additional busy hold, and =mnt_updating= is try-locked before fstrans state is
changed.

The helper uses one try-locking =vfs_suspend()= call to acquire NetBSD's
non-recursive global suspension lock, then invokes
=VFS_SUSPENDCTL(SUSPEND_SUSPEND)= directly for the other mounts while that
lock is held. Each canonical mount is suspended and synchronously flushed
before proceeding to an earlier mount. This permits final writes through vnd
while the backing filesystem is available. Aliases share the original
canonical mount's creation-order position, so a later null mount cannot
prematurely suspend its backing filesystem. Dependencies must follow that
creation order; =mnt_lower= cycles are rejected.

Genfs-backed pseudo-filesystems such as ptyfs and tmpfs use the standard
fstrans suspend handler and participate normally.  A mount with no usable
fstrans state or a suspend handler error aborts the transaction.  The helper
does not claim to quiesce an unsupported filesystem.  Layer handlers must not
recursively suspend lower mounts.

The returned =struct vfs_s2idle_mount= entries keep the mounts alive and the
global suspension lock held across device suspend.  =vfs_resume_all()= resumes
only successful entries in reverse order, releases the global owner through
=vfs_resume()=, and drops the busy holds.  ACPI calls it only after device and
storage power resume.  Any admission, suspend, or synchronous-sync error
rolls the session back and aborts selective s2idle.

GEFS supplies filesystem-specific =vfs_suspendctl= behavior.  Its handler may
flush pages, commit and drain synchronous work as the suspension owner, and
park only background policy.  It supports multiple mounts sharing one device:
a later mount's suspension-owner work is allowed until the whole set has
entered the barrier.

* Files

- =kernel/kern/vfs_s2idle.c=: generic all-mount barrier and unwind.
- =kernel/sys/vfs_s2idle.h=: kernel API used by ACPI and filesystem code.
- =kernel/kern/vfs_mount_s2idle.patch=: base mount-iterator status extension.
- =kernel/dev/acpi/acpi.c=: barrier placement and post-device resume.

* Verification

Run =tests/s2idle-barrier.sh= from this checkout for the host behavioral
protocol checks.  It covers reverse suspend/sync/resume order, layered mount
handling, skipped-iterator admission, updater and lock failures, rollback,
allocation-size accounting, and lower-mount cycle rejection.

Apply =kernel/kern/vfs_mount_s2idle.patch= with =patch -p0= from the assembled
=sys/= source root as well as copying the overlay files. The patch extends the
base iterator API; copying =vfs_s2idle.c= alone is insufficient.

The complete overlay kernel, including ACPI and the iterator extension, built
with NetBSD 11.0's native compiler and GENERIC configuration in the development
VM. Use =tests/s2idle-native/= on that kernel for an all-mount hold and resume:
build with matching headers, run =modload ./s2idletest.kmod=, then
=modunload s2idletest=. The optional =-i seconds=35= spans the syncer interval.
Keep mount administration idle during this probe. It tests the VFS protocol,
not ACPI device suspension.

The final helper passed a 35-second native hold with eight mounts: root FFS,
ptyfs, tmpfs, the /build FFS, two GEFS labels on one vnd device, FFS on a
second vnd image, and a later null mount of /build. Dirty writes preceded the
hold. Every canonical state reached =FSTRANS_SUSPENDED=; resume, the GEFS
online check, and normal cleanup succeeded. GEFS timer deadlines were set to
one second during the test. Its separate native suspension tests measured
zero reads, writes and flushes during holds, plus error and unmount rollback.
Build logs and images are under =/build/gefs-followup-20261014/= in the VM.
The laptop was not changed; physical storage/device suspend remains untested.
