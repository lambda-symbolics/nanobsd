#+TITLE: Tickless idle lost wall time; the screen would not wake (2026-10-15/16)

* Symptom
- The laptop clock ran slow (ntpdate stepped +3084 s after 80 min) and the
  kernel logged "timecounter went backwards" and "monotonic clock has gone
  backwards".
- The panel blanked after the idle timeout and no key press woke it.

* Measurement that located it
Reference: the workstation's NTP clock, sampling the laptop over ssh every
120 s window (scripts in the session scratchpad: sample.sh/clockexp.sh).

| configuration (kernel 174)  | real  | kernel date | raw TSC | raw HPET | cpu0 hardclocks | PC10 |
| tickless, maxskip 100       | 120.5 | 72          | 120.5   | 120.5    | 120.5           | 81 % |
| tickless off                | 120.5 | 120         | 120.5   | 120.5    | 120.5           | 0.2 % |

No counter stops and no tick is lost: the timecounter arithmetic loses it.

* Root cause
=binuptime()= and =tc_windup()= add =th_scale * delta= with =bintime_addx=.
=th_scale= is about 2^64 / frequency, so the 64-bit product overflows once
=delta= is worth a second.  With the periodic tick the timecounter is wound
up every 10 ms and that never happens; with the tickless idle, CPU 0 (the
only CPU calling =tc_ticktock=) sleeps up to =maxskip= = 100 ticks = 1 s,
each overflow drops about a second, and readers on other CPUs see time go
backwards meanwhile.  It explains why HPET lost time too (the overflow is
in seconds, not counter width), why =maxskip 10= was fine, and the
backwards-clock warnings.  A second limit sits behind it: the TSC
timecounter is 32 bits wide (wraps in 2.03 s at 2.112 GHz).

* Fix (kernel 175, nanobsd 7975d49; stock kern_tc.c imported in efbf725)
- =kern_tc.c=: =tc_bintime_addscaled()= splits the multiply into 32-bit
  halves (FreeBSD's large-delta method), used in =binuptime()= and
  =tc_windup()=.
- =cidle.c=: the primary CPU's skip is capped at half the selected
  timecounter's wrap interval (=tc_counter_mask * hz / tc_frequency / 2=,
  101 ticks for the TSC).

| configuration (kernel 175)       | real  | kernel date | PC10 |
| tickless, maxskip 100            | 120.6 | 121         | 98.1 % |
| tickless, maxskip 300 (cap test) | 120.5 | 121         | 98.3 % |

No clock warnings on kernel 175.  Tickless stays on (=etc/sysctl.conf=,
=rc.local=).

* The screen
Mahogany's wake path is event-driven (key press -> =hrt_idle_notify_activity=
-> armed callback -> =idle-activity= -> =idle-unblank=) and does not read the
clock.  On kernel 175, a natural blank followed by a simulated key press
through that C entry point turned eDP-1 back on ("Output eDP-1 turned on",
"Idle: panel on", modeset).  On kernel 174 the session's log showed "panel
off" without a later "panel on", but Mahogany's log is buffered and that
session ended in a reboot, so the log cannot show what happened last.  The
broken clock is the likely cause. The user has now confirmed real blank/wake
on kernel 175; the earlier failure's exact causal path was not traced.

* Patch review (7975d49, 2026-10-16)

The split multiplication is correct. Keep the always-split path in both
=binuptime()= and =tc_windup()=. Each 32-by-32-bit partial product fits in
64 bits; the explicit seconds addition and both =bintime_addx()= carries
preserve the full result, including the NTP-adjusted scale.

The kernel175 measurements confirm the fix for the reported clock loss.
Three P2 follow-ups concern cases outside those tests. The first is a defect
in the new cap; the other two are stock paths not yet adapted to long normal
windup intervals.

** P2: Cap the active counter, not just the selected one

=kernel/modules/cidle/cidle.c:208-215= reads global =timecounter=.
The sysctl setter at =kernel/kern/kern_tc.c:300-315= changes that pointer
without winding up. Readers still use =timehands->th_counter=, and the next
windup consumes its delta before switching counters at =:1016-1019=.

If an AP selects HPET after the last TSC windup but before CPU0 calculates
its cap, maxskip=300 can permit three seconds of sleep while the active
32-bit TSC wraps in 2.033602 seconds. The next windup can recover only
0.966398 seconds. The steady-counter maxskip=300 test does not exercise this
handoff. Obtain the budget from the active timehands, account for its age,
and coordinate counter changes with an already-armed idle deadline.

** P2: PPS absolute timestamps still use the overflowing product

=kernel/kern/kern_tc.c:1347-1350= adds =th_scale * delta= through
=bintime_addx()=. That delta starts at the captured timehands baseline, not
at PPS interrupt entry. A PPS event on an AP with a baseline 1.005 seconds
old can therefore receive a timestamp one second low even when processed
promptly. Use the split helper for this conversion, preserving the bounded
32-bit delta invariant. The =PPS_DEBUG= latency conversion at =:1411= has the
same arithmetic limitation. The =PPS_SYNC= product at =:1478= deliberately
computes a modulo-second frequency error and needs different treatment.

** P2: NTP catch-up can skip a leap-second boundary

=kernel/kern/kern_tc.c:993-1008= calls =ntp_update_second()= once per elapsed
second, but supplies the final second on every call. If the last timestamp
is D-0.01 and the next is D+1.01, for a UTC day boundary D, both calls receive
D+1. The insertion test in stock =sys/kern/kern_ntptime.c:465-473= requires
D modulo 86400 = 0; insertion and the TAI increment are missed. Deletion
has the analogous boundary test at =:478-485=. Process crossed boundaries
in order and propagate leap corrections into subsequent seconds and the
final timebase, separately from the deliberate large-clock-step policy.

** Verification

- 100,096 boundary/generated split-multiply model cases passed against
  exact integer arithmetic. These are model checks, not compiled C tests.
- Targeted models reproduced the counter-switch loss, PPS whole-second
  loss, and skipped insertion/deletion boundary arguments.
- Replay calls =tc_ticktock()= on every primary =hardclock()= at hz=100,
  even with interrupts disabled. The burst is not an extra interval with
  no timehands updates (=cidle.c:248-253=, =kern_clock.c:333-337=).
- Reviewed sources match 7975d49 at write-up commit 25fd96e;
  =git diff --check 7975d49^ 7975d49= passed. Review work changed only
  documentation; no kernel build, deployment, or live-machine test was run.

* Review follow-ups, kernel 176 (nanobsd 32c4737)
Astra's review (/root/astra/tickless-clock-review.org) kept the fix and found
three P2 defects nearby, all fixed: the bound now comes from kern_tc
(=tc_max_windup_ticks()=, active and selected counter, a counter switch
wakes the primary), PPS conversions add without overflow, and a sleep
crossing several seconds presents each one to =ntp_update_second= in order
(leap seconds).  cidle looks the bound up at load, so one module serves
kernels 175 and 176.  Measured with =userland/wakecensus/clock-check.sh=:

| kernel 176                     | real    | kernel | PC10   |
| tickless, maxskip 100          | 120.5 s | 121 s  | 98.5 % |
| tickless, maxskip 300          | 120.5 s | 121 s  | 98.8 % |
| maxskip 300, switch to hpet0   | 90.5 s  | 90 s   | 98.6 % |
| maxskip 300, back to TSC       | 90.5 s  | 90 s   | 98.9 % |

No clock warnings on 176.
